# 플래시카드 웹 사이트 설계

## 의도

문제가 담긴 JSON 파일을 읽어서, 문제를 플래시카드로 한 장씩 넘겨 보는 웹 사이트를 만든다. 모바일에서는 화면을 좌우로 쓸어서, PC에서는 좌우 방향키로 넘긴다. 정답은 숨겨져 있고 "펼치기"를 눌러야 보인다. 시험 공부용으로, 문제를 빠르게 넘기며 떠올려 보는 것이 목적이다.

## 목표

- 문제 JSON을 읽어 카드로 보여 준다. 문제 유형은 객관식, 단답형, 주관식 세 가지다.
- 한 번에 카드 한 장만 보인다.
- 정답은 기본으로 숨겨져 있고, "펼치기"를 누르면 보인다.
- 모바일은 좌우 스와이프, PC는 좌우 방향키로 카드를 넘긴다.
- 유형별 필터(전체 / 객관식 / 단답형 / 주관식)가 있다.
- 카드를 넘길 때, 맨 위 카드가 옆으로 밀려나 덱 맨 뒤로 들어가고 다음 카드가 올라온다.
- Vercel에 정적 사이트로 배포한다.

## 비목표 (이번 범위에서 뺀다)

- 점수, 정답 채점, 오답 기록
- 로그인, 서버, 데이터베이스
- 사용자가 JSON을 업로드하는 기능
- 과목별로 파일을 나누거나 덱을 고르는 시작 화면
- 복수 정답 객관식
- 상태 저장(현재 위치, 필터, 알아요/몰라요 표시 등). 새로고침하면 처음 상태로 돌아간다.
- 마크다운 전체 지원. 목록, 굵은 글씨, 표, 이미지, 링크는 지원하지 않는다.

## 안티 목표 (기술적으로 돌아가도 실패인 경우)

- 카드가 화면 정중앙에서 벗어난다. 펼치기 전후로 카드 높이가 바뀌어도 중심은 흔들리면 안 된다.
- 상하좌우 여백이 좁아서 화면에 꽉 차 보인다.
- 내용이 길어서 카드의 위나 아래가 화면 밖으로 잘린다.
- 펼치기 전에 정답이 어떤 식으로든 보인다. 객관식 보기에서 정답 표시가 미리 드러나는 것도 포함한다.
- 모바일에서 좌우 스와이프가 브라우저 뒤로 가기 제스처와 충돌한다.
- 버튼에 포커스가 있어서 방향키가 카드 넘김에 먹히지 않는다.

## 제약

- 프레임워크 없이 순수 HTML, CSS, JavaScript로 만든다. 빌드 단계가 없다. 외부 라이브러리도 쓰지 않는다.
- 결과물은 정적 파일(HTML, CSS, JS, JSON)뿐이다. 서버 코드가 없다.
- 문제 파일은 `questions.json` 하나다. 사이트와 함께 배포하고, 페이지가 열리면 `fetch`로 자동으로 읽는다.
- 브라우저는 `file://`로 연 페이지에서 `fetch`를 막는다. 로컬 개발에는 간단한 로컬 서버가 필요하다. 실행 방법을 README에 적는다.
- Vercel 배포는 GitHub 저장소 연결을 전제로 한다. 빌드 명령과 설정은 필요 없어야 한다.

## 데이터 모양 (확정)

맨 바깥은 문제 배열이다. 각 항목은 아래 필드를 가진다.

```json
[
  {
    "type": "multiple",
    "question": "HTTP 상태 코드 중 \"찾을 수 없음\"을 뜻하는 것은?",
    "choices": ["200", "404", "500", "301"],
    "answer": 1,
    "explanation": "요청한 주소에 자원이 없을 때 서버가 돌려주는 코드."
  },
  {
    "type": "short",
    "question": "HTTP에서 \"데이터 조회\"에 쓰는 메서드는?",
    "answer": "GET",
    "explanation": "서버에서 자원을 읽기만 할 때 쓴다."
  },
  {
    "type": "essay",
    "question": "REST API가 무엇인지 설명하시오.",
    "answer": "자원(URL)을 HTTP 메서드로 다루는 API 설계 스타일.",
    "explanation": ""
  }
]
```

- `type`은 `multiple`, `short`, `essay` 중 하나다. 화면에는 각각 "객관식", "단답형", "주관식"으로 표시한다.
- 객관식의 `answer`는 숫자이고, `choices`에서 정답 보기의 위치다. 첫 번째 보기가 0이다.
- 단답형과 주관식의 `answer`는 문자열이다.
- `explanation`은 문자열이다. 비어 있으면 화면에서 해설 줄을 숨긴다.

### 글 형식 (확정)

`question`, `choices`의 각 보기, `answer`, `explanation`의 글은 순수 텍스트다. 아래 규칙만 적용한다.

- 줄바꿈은 화면에서도 그대로 줄바꿈으로 보인다.
- 백틱 세 개(```)로 감싼 줄은 코드 블록으로, 백틱 하나(`)로 감싼 글은 인라인 코드로 보여 준다. 둘 다 고정폭 글꼴을 쓴다. 이 변환은 직접 만든 코드로 처리한다.
- 그 외 마크다운 기호는 해석하지 않고 글자 그대로 보여 준다.
- 글에 HTML이 들어 있어도 HTML로 해석하지 않고 글자 그대로 보여 준다.

## 화면과 동작

기준이 되는 모습은 확인용으로 만든 데모 `.superpowers/brainstorm/18153-1794106586/content/demo-throwaway-v3.html`이다. 의도한 모양과 조작감을 보여 주는 참고 자료이고, 코드를 그대로 가져다 쓰는 것은 아니다. 사용자가 이 데모를 보고 마음에 든다고 확인했다.

### 카드 배치

- 카드는 화면 정중앙에 놓는다. 가로로 긴 직사각형이다.
- 상하좌우에 넓은 여백을 둔다.
- 펼치기를 하면 카드가 위아래로 늘어난다. 이때도 카드의 중심은 화면 중앙에 있어야 한다.
- 모바일 세로 화면에서도 카드는 가로폭을 기준으로 잡되 사방 여백을 유지한다. 폰을 눕히라고 요구하지 않는다.
- 객관식 보기는 PC에서는 두 열, 좁은 화면에서는 한 열로 보인다.
- 페이지 자체는 스크롤하지 않는다.

### 카드 내용

- 위쪽에 유형 라벨(객관식, 단답형, 주관식)과 문제를 보여 준다.
- 객관식은 문제 아래에 보기를 번호와 함께 나열한다.
- 카드 아래에 "▼ 펼치기" 버튼이 있다. 누르면 정답과 해설이 카드 안에서 펼쳐지고, 버튼은 "▲ 접기"로 바뀐다. 다시 누르면 접힌다.
- 객관식은 펼쳤을 때 정답 보기가 강조된다(초록색 테두리와 배경). 접으면 강조도 사라진다.
- 다른 카드로 넘어가면 새 카드는 항상 접힌 상태로 시작한다.

### 긴 카드 (확정: 글자 크기 자동 축소)

- 카드가 화면의 여백을 뺀 영역보다 길어지면, 글자 크기를 줄여서 카드가 그 영역 안에 들어오게 한다. 스크롤은 쓰지 않는다.
- 줄이는 대상은 카드 안의 모든 글이다. 문제, 보기, 정답, 해설, 버튼이 같은 비율로 줄어든다.
- 카드가 바뀔 때, 펼치기와 접기를 할 때, 화면 크기가 바뀔 때(창 크기 조절, 폰 회전) 다시 맞춘다.
- 글자 크기는 현재 카드의 현재 상태(접힘 또는 펼침)를 기준으로 맞춘다. 그래서 펼칠 때 글자가 더 작아질 수 있고, 접으면 다시 커진다. (제 임시 결정)
- 글자 크기에 하한을 둔다. 하한까지 줄여도 카드가 영역을 넘으면, 그때만 카드 안쪽에서 세로 스크롤을 허용한다. 이 경우에도 카드는 화면 안에 머물고 잘리지 않는다. 하한의 구체적인 값은 만드는 사람이 정한다. (제 임시 결정)

### 카드 넘기기

- PC: 오른쪽 방향키는 다음 카드, 왼쪽 방향키는 이전 카드다.
- 모바일: 왼쪽으로 쓸면 다음 카드, 오른쪽으로 쓸면 이전 카드다. 가로 이동량이 50px보다 크고 세로 이동량보다 클 때만 넘김으로 본다. 카드 안쪽 세로 스크롤이 생기는 경우(위 "긴 카드"의 하한 처리)에는 그 스크롤을 막지 않는다.
- 데모에서 PC 마우스 드래그로도 넘겼다. 개발 중 확인용이었고, 필수는 아니다. 최종 결정은 만드는 사람에게 맡긴다.
- 넘김 애니메이션이 도는 동안 들어오는 추가 입력은 무시한다.
- 애니메이션: 카드 뒤에 남은 카드가 한두 장 겹쳐 쌓여 보인다. 넘기면 맨 위 카드가 쓴 방향으로 살짝 기울며 밀려난 뒤 덱 맨 뒤로 들어가고, 다음 카드가 앞으로 올라온다. 약 0.5초다.
- 첫 번째 카드에서 이전으로 넘기면 아무 일도 일어나지 않는다.

### 순서와 끝 처리

- 페이지를 열 때마다 모든 카드를 무작위로 섞는다. 새로고침하면 순서가 바뀐다.
- 마지막 카드에서 더 넘기면(다음 방향) 카드를 다시 섞고 첫 카드부터 다시 시작한다. 이때도 같은 덱 넘김 애니메이션을 쓴다. 현재 필터가 걸려 있으면 필터를 유지한 채 전체를 다시 섞고, 그 필터의 첫 카드부터 보여 준다.

### 필터

- 화면 위쪽 가운데에 "전체 / 객관식 / 단답형 / 주관식" 버튼이 있다. 버튼마다 해당 문제 수를 작게 표시한다. 하나만 고를 수 있다.
- 필터를 바꾸면 이미 섞인 순서 안에서 해당 유형만 걸러 보여 주고, 첫 카드로 돌아간다. 필터를 바꿀 때는 다시 섞지 않는다.
- 필터 버튼을 누른 뒤에도 방향키가 동작해야 한다.

### 진행 표시

- 카드 밖, 화면 아래쪽 가장자리에 "3 / 20" 형식의 작은 글씨로 표시한다. 필터가 걸려 있으면 그 묶음 기준이다.

### 오류

- `questions.json`을 읽지 못하거나 문제가 하나도 없으면, 카드 대신 짧은 오류 안내를 화면 가운데에 보여 준다.

## 배포

- 코드를 GitHub 저장소에 올리고 Vercel에 연결한다. `git push`마다 자동으로 배포된다.
- 빌드 명령이 없으므로 Vercel 프로젝트 설정에서 프레임워크는 "Other", 빌드 명령은 비운다.

## 만드는 사람에게 맡긴다

- 파일 구성(HTML, CSS, JS를 몇 개로 나눌지)
- 색, 글꼴, 정확한 여백 크기, 애니메이션 곡선 같은 시각 디테일. 데모를 기준으로 한다.
- 글자 크기를 줄이는 구체적인 방법과 하한 값
- 개별 문제 항목의 형식이 잘못됐을 때의 처리
- 짝이 맞지 않는 백틱처럼 코드 서식이 어긋난 글의 처리. 어긋난 부분은 글자 그대로 보여 주면 된다.
- 샘플 `questions.json`의 내용. 개발과 확인용으로 데모의 샘플 문제를 쓰고, 코드 블록과 긴 글 예시도 몇 개 넣는다.
- 로컬 서버 실행 방법의 구체적인 안내

## 사용자가 정한 것과 임시 결정의 구분

### 사용자가 정한 것

- 객관식, 단답형, 주관식을 카드로 한 장씩 본다.
- 정답은 숨겨져 있고 "펼치기"로 본다.
- 카드는 정중앙에, 사방 여백은 넓게. 가로로 긴 카드.
- 모바일은 좌우 스와이프, PC는 좌우 방향키.
- 카드가 덱 뒤로 넘겨지는 애니메이션.
- 유형 필터 버튼(전체 / 객관식 / 단답형 / 주관식).
- 순수 HTML/CSS/JS, Vercel 정적 배포.
- 문제 JSON을 사이트와 함께 배포하고 자동으로 읽는다. 파일은 하나다.
- JSON 모양. 객관식 `answer`는 숫자.
- 상태 저장 없음.
- 열 때마다 자동으로 섞는다.
- 마지막 카드에서 더 넘기면 다시 섞고 처음부터 시작한다.
- 카드가 화면보다 길어지면 글자 크기를 자동으로 줄여 맞춘다.
- 글 형식은 순수 텍스트이고, 코드 서식(```와 `)만 직접 처리해서 지원한다.

### 제 임시 결정 (사용자가 확정하지 않았다)

- 왼쪽으로 쓸면 다음 카드, 오른쪽으로 쓸면 이전 카드.
- 객관식은 펼칠 때 정답 보기를 초록색으로 강조한다.
- 필터 버튼에 문제 수를 표시한다. 필터를 바꾸면 첫 카드로 돌아가고, 다시 섞지는 않는다.
- 진행 표시를 카드 밖 아래쪽에 둔다.
- 필터가 걸린 상태에서 마지막 카드를 넘기면 필터를 유지한 채 다시 섞는다.
- `explanation`이 비어 있으면 해설 줄을 숨긴다.
- 첫 카드에서 이전으로 넘기면 아무 일도 하지 않는다.
- 파일을 못 읽거나 문제가 없으면 화면에 오류 안내를 보여 준다.
- 넘김 애니메이션이 도는 동안 추가 입력을 무시한다.
- 글자 크기를 현재 카드의 현재 상태(접힘 또는 펼침) 기준으로 맞춘다. 펼치면 글자가 줄 수 있다.
- 글자 크기에 하한을 두고, 하한에서도 넘치면 카드 안쪽 세로 스크롤을 허용한다. 사용자는 "스크롤 없이 글자만 줄이기"를 골랐으므로, 이 예비 규칙은 사용자가 고른 것과 어긋날 수 있다.
- 코드 서식이 아닌 마크다운 기호와 HTML은 글자 그대로 보여 준다.
- 문서 위치를 `docs/superpowers/specs/`로 정했다. git 저장소가 아니라서 커밋하지 않는다.
- `.superpowers/` 폴더는 `.gitignore`에 넣는 것이 좋다. 목업과 데모가 들어 있다.
