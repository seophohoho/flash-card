# 월말 평가 탭 설계

## 의도
월말 평가 전날, 실습·과제 42개(`ws_hw/`)를 "정답이 채워진 스켈레톤 코드 + 실행 출력"으로 읽고 외운다.
시험은 빈칸을 직접 채우는 방식이므로, 정답이 어디였는지 눈에 띄는 것이 핵심이다.

## 목표
- 상단 탭에 "월말 평가" 추가 (문제 카드 / 과목평가 / 월말 평가).
- 문제 1개 = 1편. 문제 설명, 정답이 강조된 코드, 실행 출력, 핵심 개념을 보여준다.
- 읽기 전용. 입력창과 채점 없음.

## 비목표
- 정답 가리기, 직접 입력, 자동 채점.
- ws_hw 문제를 다시 실행해 출력을 새로 만들지 않는다. ANSWER.md의 출력을 그대로 쓴다.

## 접근 (선택: A)
- A. 변환 스크립트가 ws_hw를 읽어 `exam/exam.json` 생성 ← 선택
- B. 에이전트가 JSON을 직접 작성 (오타 위험)
- C. ANSWER.md를 그대로 렌더 (빈칸 강조 불가)

## 구성
- `scripts/build-exam.mjs`: `ws_hw/` 폴더들을 읽어 `exam/exam.json`을 만든다. Node 전용, 외부 패키지 없음. 결과 JSON은 저장소에 커밋한다(Vercel은 빌드 없이 정적 배포).
- `js/exam.js`, `js/exam-render.js`: 탭 화면. 과목평가의 목차 시트·페이저·해시(`#exam-3`)와 같은 방식.
- `css/exam.css`, `index.html` 탭 버튼, `main.js` 모드 추가.
- `tests/build-exam.test.js`: 파서 테스트.

## exam.json 항목
`id`(예: ws_2_1), `kind`(실습/과제), `title`, `part`(I~VI), `description`(README 학습목표·요구사항 원문), `code`(완성 코드), `highlights`(강조할 구간), `output`, `concepts`(핵심 개념 원문), `extra`(서술 답안 등 그 외 절).

## 예외 처리 (스크립트 담당)
- 빈칸 위치: 스켈레톤과 완성 코드를 줄 단위로 비교한다. 스켈레톤 줄의 `____`를 `(.+?)`로 바꾼 정규식으로 채워진 부분만 잡는다. 안 맞으면 바뀐 줄 전체를 강조한다.
- 빈칸 0개(hw_2_2, hw_4_2, hw_4_4, hw_5_2 등): 강조 없이 완성 코드만 보여준다. hw_2_2는 정답 표의 값을 코드에서 찾아 강조를 시도하고, 실패하면 강조 없음.
- `skeleton_p.py`, `skeleon_p.py`(오타 파일명), 다른 `.py` 파일: 무시하고 `skeleton.py`만 비교한다. ANSWER.md가 완성 코드를 가진 쪽을 기준으로 한다.
- ws_4_1처럼 코드 블록이 없는 문제: 절차 절을 본문으로 보여준다.
- 절 제목 변형(`실행 출력`/`실제 실행 출력`, `빈칸 정답`/`빈칸별 정답`): 별칭 목록으로 처리.
- 이상 상황(완성 코드 없음, 출력 없음)은 스크립트가 경고를 출력하고 해당 칸을 비운다. 멈추지 않는다.

## 제가 정한 부분 (바꾸고 싶으면 말해 주세요)
- 정렬: ws → hw가 아니라 단원(I~VI) 순, 단원 안에서 ws, hw 순.
- README 설명은 기본 접힘, 코드와 출력은 기본 펼침.
- 강조 색은 노란 배경 하나.
- 핵심 개념과 서술 답안은 코드 아래에 마크다운으로 표시(기존 `markdown.js` 재사용).

## 검증
- 스크립트 실행 시 42개 모두 처리, 경고 목록 출력.
- `node --test` 통과.
- 로컬 서버에서 탭을 열어 샘플 5개(빈칸 많음, 빈칸 0, 코드 없음, 긴 출력, 서술 답안) 눈으로 확인.
